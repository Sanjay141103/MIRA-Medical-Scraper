Prompt Engineering Documentation

Project: MIRA-Lite AI Medical Directory Scraper Candidate: Sanjay Mathivanan Role: AI Growth & Automation Associate
Executive Summary & Methodology:
This document chronicles the iterative prompt engineering history used to build MIRA-Lite, an automated AI agent that turns unstructured Australian clinic websites into clean, verified General Practitioner directories. The solution progresses from low-level DOM scraping through semantic extraction to interactive deployment in Gradio with robust JSON error-recovery.
Stage 1: Establishing Scraper Architecture & Anti-Bot Protection
Architecture Setup
Prompt 1 (Initial Logic):
"Write a Python script using requests and BeautifulSoup to scrape all paragraph and header text from a medical clinic's 'Our Doctors' webpage, handling basic HTTP headers to avoid being blocked."
Engineering Rationale & Technical Objective:
Medical directories frequently use web applications with basic bot protection (Cloudflare, User-Agent filtering). The initial prompt established a solid baseline with proper browser emulation headers and multi-tag DOM extraction (h1, h2, h3, p, div) to capture all unstructured text without losing context.
Stage 2: Semantic Intelligence & Strict Structured Output
AI Integration
Prompt 2 (Adding AI Data Intelligence):
"The scraped text is too messy. Integrate the Google Gemini API (or OpenAI API). Write a prompt inside the Python script that takes the scraped text and asks the LLM to extract all Doctor Names, Specialties, and Contact Details, forcing the LLM to output ONLY a strict JSON array of objects."
Engineering Rationale & Technical Objective:
Traditional regex scraping fails across varying clinic layouts. By feeding unstructured text into Gemini Flash 1.5 with few-shot example formatting and strict zero-shot constraints, the AI understands messy qualification abbreviations (e.g. FRACGP, MBBS) and doctor schedules while forcing a predictable machine-readable schema.
Stage 3: End-to-End User Experience & Pipeline Automation
UI & Pipeline
Prompt 3 (Adding the UI & Pandas):
"Wrap this pipeline into a Gradio web UI. Have the Gradio app take a URL string as input, run the scraping and LLM extraction, load the resulting JSON into a Pandas DataFrame, and display the DataFrame in the UI while also providing a downloadable CSV file."
Engineering Rationale & Technical Objective:
Raw scripts are not operational for growth and research teams. This prompt wraps the entire extraction logic into a self-service Gradio UI. The parsed JSON feeds directly into a Pandas DataFrame, automatically rendering an interactive data table and exporting a ready-to-use CSV file for outreach or database seeding.
Stage 4: Edge-Case Hardening & Markdown Sanitization
Production Resilience
Prompt 4 (Refining the AI Prompt - Troubleshooting):
"The LLM is sometimes adding markdown formatting like ```json to the output, which breaks the json.loads() function. Update the internal system prompt to strictly forbid markdown formatting and strip any backticks before parsing the JSON into Pandas."
Engineering Rationale & Technical Objective:
LLMs frequently wrap code and JSON blocks in markdown fences (```json ... ```), causing fatal json.decoder.JSONDecodeError exceptions. This prompt implemented two layers of defense: (1) an explicit prompt negative constraint ("CRITICAL: Output ONLY a valid JSON array. Do not include markdown formatting"), and (2) programmatic string cleaning (replace('```json', '').replace('```', '')) to ensure 100% parsing reliability.
